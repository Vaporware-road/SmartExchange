High-level goals





Frontend (Vue 3): Turn TelegramMessageView.vue into a 4-tab "Telegram Management Hub" (Messenger, Bot Setup, Channels, Automation) using glassmorphism BaseCard/card-luxury and input-luxury, with smooth tab transitions and full i18n/RTL support.



Analytics: Move any Telegram channel analytics from the Telegram area into a new Telegram Engagement section inside [frontend/src/views/analysis/AnalyticsView.vue](frontend/src/views/analysis/AnalyticsView.vue), backed by existing or extended analysis endpoints and rendered with chart.js.



Backend (Django): Leverage existing TelegramBot/TelegramChannel models in [backend/telegram_app/models.py](backend/telegram_app/models.py), add a new AutoPostConfig model and CRUD APIs, and keep automation "config-only" (no scheduler wiring yet).



Stability: First, resolve the UpdatePriceView loading bug so price data flows reliably through the system.

Step 1 – Fix UpdatePriceView loading bug





Identify the bug: UpdatePriceView.vue currently calls priceApi.list() and assumes a plain array response, while PricesView.vue already handles both array and paginated { results: [...] } shapes.



Planned fix:





Prefer introducing priceApi.get(id) in [frontend/src/services/api.js](frontend/src/services/api.js) hitting a new or existing GET /api/prices/<id>/ endpoint; if adding a new endpoint is not desirable, at minimum update UpdatePriceView.vue to handle both data and data.results when searching by id.



Add a final v-else branch in UpdatePriceView.vue to show a user-friendly error card (using card-luxury) when priceType is missing, instead of rendering a blank area.



Ensure loading flags and error handling follow the same pattern as PricesView.vue and BulkUpdateView.vue so the UX is consistent.
